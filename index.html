Step 1

The Cast of Characters (Keys)

Before you send a single message, your app generates a set of cryptographic keys. These are simply long strings of numbers. E2EE uses Asymmetric Cryptography: a Public Key (Open Padlock) that anyone can use to lock a message, and a Private Key (The Key) that only you have to unlock it.

Step 2

The Handshake (X3DH)

When Bob wants to message Alice, he fetches her "Public Bundle" from the server. Using a protocol called X3DH, Bob's phone combines his keys with Alice's keys to calculate a shared Root Key. Crucially, the server never sees this Root Key.

Step 3

The Double Ratchet

This is the engine of modern encryption. We don't use the Root Key for everything. Instead, we "ratchet" forward. Each message has its own unique key derived from the previous one. Once a message is decrypted, its key is deleted forever (Forward Secrecy).
